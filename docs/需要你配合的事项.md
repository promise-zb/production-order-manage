# 需要你配合的事项

Demo 现在就能在本机跑，不需要先建数据库。下面这些是接到 Deno 和 Netlify 时才要你做的。

本地启动见仓库根目录的 `README.md`。账号是 `admin` / `admin`。

## 1. 分工

接口已经改成 Node.js + TypeScript + Express。[Deno Deploy](https://console.deno.com/promisezhangbo) 可以运行这个 Node 程序。入口文件是 `backend/server.ts`。

- 数据库：用 Deno Deploy 上的 PostgreSQL（Prisma Postgres）。没填连接串时，本机用 SQLite 文件。
- 接口：Express，本机端口 8080，也可以部署到 Deno Deploy。
- 页面：放到 [Netlify](https://app.netlify.com/teams/promise-zhangbo/projects)。

不要选 Deno KV。这套接口用的是 PostgreSQL 或 SQLite。

## 2. 创建 PostgreSQL

官方说明：[Databases](https://docs.deno.com/deploy/reference/databases/)、[Prisma Postgres 接入](https://www.prisma.io/docs/guides/integrations/deno)。

1. 打开 https://console.deno.com/promisezhangbo 并登录。
2. 进入 Databases，点 Provision Database，引擎选 Prisma Postgres。
3. 起一个名字，例如 `production-order`，区域选离你近的，然后创建。
4. 复制 **Production connection string**。必须是 `postgresql://` 开头。不要用 `prisma+postgres://`，那个只有 Prisma 客户端能用。
5. 如果字符串里没有 `sslmode`，在末尾加上 `?sslmode=require`。
6. 在 `backend` 目录复制一份配置：

```bash
cd backend
cp .env.example .env
```

7. 把连接串填进 `.env`：

```bash
DATABASE_URL=postgresql://用户名:密码@主机:5432/数据库名?sslmode=require
```

8. 在仓库根目录重新执行 `pnpm dev`。连上之后程序会自己建 `orders` 表。空表时还会写入 6 条示例订单。不想要示例数据时，把 `.env` 里的 `SEED` 改成 `0`。

也可以不靠程序建表，把下面的 SQL 拿到数据库里执行。列类型和程序里的建表语句一致，时间用文本保存，是为了和本机 SQLite 共用同一套读写代码。

```sql
CREATE TABLE IF NOT EXISTS orders (
  id BIGSERIAL PRIMARY KEY,
  order_no TEXT NOT NULL UNIQUE,             -- 订单编号
  name TEXT NOT NULL,                        -- 名称
  alias TEXT NOT NULL DEFAULT '',            -- 别名
  customer_name TEXT NOT NULL DEFAULT '',    -- 客户名称
  customer_address TEXT NOT NULL DEFAULT '', -- 客户地址
  contact_name TEXT NOT NULL DEFAULT '',     -- 联系人
  contact_phone TEXT NOT NULL DEFAULT '',    -- 联系电话
  product_name TEXT NOT NULL DEFAULT '',     -- 产品名称
  style_no TEXT NOT NULL DEFAULT '',         -- 款号
  status TEXT NOT NULL DEFAULT 'pending',    -- pending/processing/partial_shipped/done/cancelled
  order_qty INTEGER NOT NULL DEFAULT 0,      -- 订单总数
  unit_price DOUBLE PRECISION NOT NULL DEFAULT 0,      -- 单个金额
  total_amount DOUBLE PRECISION NOT NULL DEFAULT 0,    -- 订单总金额
  today_ship_qty INTEGER NOT NULL DEFAULT 0,           -- 当天出货数量
  shipped_qty INTEGER NOT NULL DEFAULT 0,              -- 累计已出货数量
  remain_qty INTEGER NOT NULL DEFAULT 0,               -- 剩余未完成数量
  material_done_at TEXT,                     -- 单个材料完成时间，可空
  order_total_hours DOUBLE PRECISION NOT NULL DEFAULT 0, -- 订单完成总时间，单位小时
  order_date TEXT,                           -- 下单日期
  delivery_date TEXT,                        -- 交货日期
  remark TEXT NOT NULL DEFAULT '',           -- 备注
  created_at TEXT NOT NULL,                  -- 创建时间
  updated_at TEXT NOT NULL                   -- 修改时间
);
```

状态实际存英文代码，页面上显示中文：

| 代码            | 含义     |
| --------------- | -------- |
| pending         | 待生产   |
| processing      | 生产中   |
| partial_shipped | 部分出货 |
| done            | 已完成   |
| cancelled       | 已取消   |

两个数字由程序在保存和导入时重算，表格里看到的就是算好的结果：

- 订单总金额 = 单个金额 × 订单总数
- 剩余未完成数量 = 订单总数 − 累计已出货数量

当天出货数量只表示这一天出了多少，不参与剩余数量的计算。

我补上的字段：订单编号、客户名称、联系人、联系电话、产品名称、款号、状态、累计已出货数量、下单日期、交货日期、备注。

时间字段的含义按这个约定来写的：单个材料完成时间是一个时间点；当前订单完成的总时间是小时数。如果要改成别的含义，告诉我。

## 3. 部署前端到 Netlify

1. 打开 https://app.netlify.com/teams/promise-zhangbo/projects 。
2. 用 Git 仓库导入。这个仓库如果还没有远程地址，先告诉我，我再帮你看怎么推。
3. Base directory 留空，使用仓库根目录。
4. Build command 填 `pnpm --filter production-order-frontend build`。
5. Publish directory 填 `frontend/dist`。包管理器选 pnpm。
6. 添加环境变量 `VITE_API_BASE`，值是接口的公网地址，不要以 `/` 结尾，例如 `https://production-order-api.example.deno.net`。
7. 改完这个变量要重新构建。Vite 会在构建时把地址写进页面，只改配置不重新构建不会生效。

本地在根目录执行 `pnpm dev` 时不要填 `VITE_API_BASE`。开发服务器会把 `/api` 转到 `http://127.0.0.1:8080`。

接口还在本机时，Netlify 上的页面访问不到它。需要先有一个公网地址，再填 `VITE_API_BASE`。

## 4. 接口上线时要改的环境变量

`backend/.env.example` 里有全部项。正式使用前至少改这三项：

- `ADMIN_USER`
- `ADMIN_PASSWORD`
- `AUTH_SECRET`（随便一长串随机字符，用来给登录令牌签名）

登录令牌 24 小时过期。接口使用 `Authorization: Bearer <token>`。

## 5. Excel

页面上可以下载模板。第一行是表头，从第二行开始是数据。导入按新增处理，订单编号已存在的行会失败，不会覆盖旧数据。

表头：

订单编号、名称、别名、客户名称、客户地址、联系人、联系电话、产品名称、款号、状态、订单总数、单个金额、订单总金额、当天出货数量、累计已出货数量、剩余未完成数量、单个材料完成时间、订单完成总时间(小时)、下单日期、交货日期、备注。

状态可以写中文，例如「待生产」。订单总金额和剩余未完成数量可以空着，导入时会重算。

导出的文件多三列：系统 ID、创建时间、修改时间。这三列再导回去会被忽略。
